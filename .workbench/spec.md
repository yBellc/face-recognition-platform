# 工作台定义

这是一个围绕“图片识别任务”运转的桌面控制台：操作员导入重点关注对象参考照片和现场图片，系统定位一张图中的全部人脸并给出候选；复核员在同一工作区看到人脸框、候选对象、相似度、质量说明和复核动作；管理员负责项目隔离、账号、阈值、授权、保留和导出。

## 首屏结论条

首屏优先呈现：今日上传数、检测人脸数、待复核数、失败数、当前模型版本和最近任务耗时。没有数据时明确显示“还没有任务，先上传一张现场图片”，不使用虚构指标。

## 页面与操作路径

1. 工作台：查看今日状态，进入“录入对象 / 上传图片 / 复核结果”。
2. 对象库管理：创建对象、上传 1 张或多张参考图、按文件夹批量导入、删除错误照片或整个对象。
3. 现场图片识别：选择项目，上传单张图片；任务完成后进入复核。
4. 识别结果与复核：左侧为分页任务队列，中间为带编号人脸框的原图，右侧只展示当前人脸的候选；确认、排除、存疑、无法判断和归档都在固定底栏完成。
5. 评测报告：查看公开数据集试跑结果、阈值校准样本和误报/漏报证据。
6. 系统治理：项目、账号角色与授权、隐私保留策略、运行监控和导出。

## 导出与删除规则

- CSV 默认按“人脸结果行”导出：有候选时每行对应一个候选人脸；无候选/无法判断时仍保留一行空对象编号记录，包含图片 ID、人脸 ID、决策带、复核状态、时间和模型版本。
- 治理页可导出“当前项目全部图片”或“全部项目汇总”；复核页可导出“当前单张图片”。
- 归档只移出待复核队列，保留审计记录；项目/对象/参考照片的删除需二次确认并写审计日志。
- 人脸参考照片是敏感数据，默认不提供公开自助注册；由管理员创建账号并授予项目访问权限。

## 数据模型底线

Project → Subject → ReferenceImage；Project → ProbeImage → FaceDetection → MatchCandidate → ReviewDecision。每个实体都带项目访问边界和审计事件。质量不足、侧脸、遮挡、逆光或车窗反光只能输出“无法判断”，不能硬匹配。

## 冷启动与指标

没有内部数据时使用公开数据集做流程验证，不把公开数据结果当生产准确率。阈值在授权验证集上按目标误报率/漏报率重新校准；展示页必须同时给出样本数、模型版本、p50/p95 耗时、失败率和队列积压。

## 给实现方

桌面端采用固定侧栏、顶栏状态、可滚动内容区和固定操作底栏；动画只用于页面淡入、卡片错峰、扫描进度和状态反馈，采用 transform/opacity 并支持 reduced-motion。所有业务动作都要有成功/失败反馈、禁用态、空态和可追溯记录。
